What we document

Five platforms in scope.

Choose the platforms you run. Each section records its scope, its collection date and any gaps in the evidence.

  • Microsoft Azure

    Subscriptions, resource groups, virtual networks, subnets, peerings, network security groups and virtual machines.

  • Amazon AWS

    Accounts, VPCs, subnets, route tables, security groups and instances.

  • Google Cloud Platform

    Projects, VPC networks, subnets, firewall rules and instances.

  • VMware NSX

    Tier-0 and tier-1 gateways, segments and the distributed firewall: policies, rules and what they apply to.

  • VMware ESXi and vCenter

    Clusters, hosts and ESXi builds, cluster settings, virtual machines, datastores and virtual switches.

  • Audit evidence and coverage

    Included with every report: the scope read on each platform, the date it was collected and anything that could not be read.

How it works

From read-only access to an as-built record.

Three steps take you from agreed scope to documentation your engineers and reviewers can rely on.

  1. 1

    Connect

    Agree the platforms in scope, then grant read-only access to each one.

  2. 2

    Document

    Record what exists, how it is configured and how it connects. Note the scope, collection date and evidence gaps.

  3. 3

    Review and refresh

    Give engineers the findings in priority order. Repeat the collection to show what changed.

What access we need

Read-only access to each platform in scope. Nothing is created, changed or deleted.

  • Microsoft Azure

    A read-only role on each subscription in scope.

  • Amazon AWS

    A read-only role in each account in scope.

  • Google Cloud Platform

    A read-only role on each project in scope.

  • VMware

    A read-only account in vCenter and in NSX Manager.

Findings and evidence

More than an inventory. Findings with their evidence.

Each finding names what it affects, the evidence it rests on and the next step.

  • For engineers: a prioritised list

    Findings in priority order, each traced to the resource, rule or setting it comes from.

  • For reviewers: one current record

    The same structure for every platform, with the scope, collection date and coverage stated.

  • Between refreshes: what changed

    Repeat the collection to show what was added, removed or reconfigured since the last report.

The finding above is illustrative and uses the fictional Riverside Technology Group estate. Findings are based on what was read from each platform at the time of collection, and should be reviewed by your engineers before any change is made.

Questions about Sysopty

Which platforms are in scope?

Microsoft Azure, Amazon AWS, Google Cloud Platform, VMware NSX, and VMware ESXi and vCenter. You choose which of them to include.

What access is needed?

Read-only access to each platform in scope. See what access we need.

Does collection change anything?

No. Collection reads configuration and inventory through read-only access. It does not create, change or delete anything.

Are the reports available now?

Reporting capabilities are in development. The report previews on this page are illustrative layouts that use synthetic data for a fictional organisation.
